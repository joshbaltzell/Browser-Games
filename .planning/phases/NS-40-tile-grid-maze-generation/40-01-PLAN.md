<objective>
Add the data layer for Neon Gauntlet's procedural level system: the mulberry32 seeded PRNG,
the coarse 4×4 room-slot graph generator (random walk producing 3–8 rooms), and the
room-type assignment algorithm (Start = first slot, Boss = farthest-from-Start by BFS,
Shop/Elite inserted among Normal rooms). Level generation fires from handleFirstGesture().

level skeleton: which room slots exist, their types, their connections, and their empty
Uint8Array grids (walls only — no interior carving yet).

Purpose: Establish the data structures and entry point that Plans 02 and 03 build on.
Plan 02 carves interior mazes into the grids. Plan 03 renders them.

           return function() {
             seed |= 0;
             seed = seed + 0x6D2B79F5 | 0;
             var t = Math.imul(seed ^ seed >>> 15, 1 | seed);
             t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;

           };
         }

       This is a standard mulberry32 implementation. It returns a closure (stateful PRNG).

    Add generateLevel(levelNumber, seed) to game.js, inserted after the mulberry32 function.

    == generateLevel() algorithm ==

    The function must:
    1. Initialize: `const rng = mulberry32(seed);`
    2. Build a coarse 4×4 slot grid (16 slots, indices 0–15, row-major: row*4+col).
       Slot adjacency: N = idx-4, S = idx+4, E = idx+1 (same row), W = idx-1 (same row).
       Same-row guard for E/W: `Math.floor(idx/4) === Math.floor(neighbor/4)`.
    3. Random walk to place rooms (per D-04):
       - roomCount = (levelNumber <= 2) ? 3 + Math.floor(rng() * 2) : 5 + Math.floor(rng() * 4);
         (level 1–2 → 3 or 4 rooms; level 3+ → 5–8 rooms)
       - Start at a random slot. Walk randomly into unvisited adjacent slots until roomCount
         slots are placed. If walk gets stuck (no unvisited neighbors), backtrack using a
         stack. This is the iterative DFS / random walk approach — no recursion needed for
         the slot-level graph (only the interior maze in Plan 02 uses recursion).
       - Store placed slots as an array `placedSlots` (in placement order).
       - Store connections as a Set of strings `"idx1-idx2"` (smaller idx first) for
         axis-aligned adjacent slot pairs that are both placed.
    4. Room-type assignment (per D-06):
       - Start = placedSlots[0].
       - Boss = slot farthest from Start by BFS hop count over the connection graph.
         (Run BFS from Start over connections; Boss = slot with max hops.)
       - Among remaining slots (neither Start nor Boss):
         * One becomes ELITE, one becomes SHOP (inserted at indices 1 and 2 of the
           non-Start non-Boss list, or randomly chosen if more than 4 total remain normal).
         * All others become NORMAL.
       - If fewer than 5 total slots exist (3 or 4), assign type by index:
         [0]=START, [last]=BOSS, [1]=SHOP (if 3 rooms skip ELITE), [others]=NORMAL.
         Retry if cannot fit all 5 types (max 10 retries, then use fallback 2-room layout).
    5. Build room objects (per D-02, D-03):
       For each placed slot, create:
         {
           id: slot index in placedSlots array,
           slotIdx: slot index in the 4×4 grid (0–15),
           type: "START" | "NORMAL" | "ELITE" | "SHOP" | "BOSS",
           rows: 15,   // Normal/Elite/Shop: 15×15; Boss: 21×21; Start: 15×15
           cols: 15,
           grid: null, // filled by Plan 02 interior carving
           spawnPoint: null, // filled by Plan 02
           spawnList: [],    // filled by Plan 02
           connections: [],  // directions this room connects to: ["N","E","S","W"] subset
         }
       Override rows/cols for Boss room: rows=21, cols=21.
       Override rows/cols for Start room: rows=15, cols=15 (open layout, same size as Normal).
    6. Populate room.connections arrays: for each connection string in the connections Set,
       determine direction relative to each room and push to that room's connections array.
       E.g. if slot A is north of slot B, A.connections.push("S") and B.connections.push("N").
    7. Fallback (per D-14, D-15, UI-SPEC BFS Assertion Behavior):
       Wrap the entire generation in a retry loop (max 10 iterations). On each retry,
       regenerate with `seed + retryCount`. If all retries fail, produce a minimal fallback:
         2 rooms: Start (slot 5) + Boss (slot 6), connected E–W.
       Log the fallback with: console.warn("[Phase40] Level generation failed after 10 retries — using fallback 2-room layout");
    8. Room-graph BFS assertion (per D-14): After placing rooms, verify all rooms are
       reachable from Start by traversing the connections. Any unreachable room triggers a
       retry. This is graph-level BFS only — tile-level BFS is Plan 02.
    9. Console log on success (per UI-SPEC Console Output section):
       console.log("[Phase40] Level", levelNumber, "| seed:", seed, "| rooms:", rooms.length, "| types:", rooms.map(r => r.type).join(", "));
    10. Assign to module-level vars:
       currentLevel = { rooms, connections: connectionsSet, seed, levelNumber };
       currentRoom = rooms.find(r => r.type === "START");
    11. Return currentLevel.
